# 冒険者をマスタデータへ登録する

`GuildSimulator.Game/Data/adventurers.json` に1人足す作業です。JSONを書くこと自体は
簡単ですが、**数値の取り違えは `--validate-master` を素通りします**（値としては正しい
JSONなので）。壊れていることに気づくのは、ゲームを遊んで「なぜかこの子だけ強い」と
思ったときになります。だからこの手順は、書く前に数値を作り、書いたあとに数値を確かめます。

## いちばん間違えやすいところ

**強さは「素質」と「レベル」の2階建てです。**

```
7能力の合計 = 素質 + (defaultLevel − 1)      ※レベル1につき1点だけ伸びる
素質         = 帯の基準65 + レアリティ上乗せ（帯より1段上なら +5、上限70）
```

ここで2つ、放っておくと必ず踏む落とし穴があります。

- **素質は7能力で数えます。** 体力・精神・筋力・敏捷・知力の5つだけで比べてはいけません。
  体格(SIZ)と容姿(APP)はレベルで伸びないぶん、最初から素質の一部として配られています。
  5能力だけで見ると、体格19を取ったグリム（5能力44）が名簿で最弱に見えますが、
  素質としてはロビンやダグとまったく同じ65です
- **レアリティは素質にだけ乗ります。** レベルを上げてレアらしくするのは筋が違います。
  それは「経験を積んだ人」であって「素質に恵まれた人」ではないからです

上乗せは **+5 の1段だけ**で、70が名簿全体の素質上限です。レアリティが2段上でも70より
上には行きません（マルシルはF帯のRareですが、Uncommonのサトル・ゴードンと同じ70です）。
レベルで縦に伸ばす帯の設計を、レアリティが横から飛び越えないようにするためです。

## 手順

### 1. その冒険者を決める

先に人物を決めます。名前・種族・職業・性別・体格・容姿・背景。数値はそのあとです。
足りない情報はユーザーに聞いてください。とくに次は本人にしか決められません。

- **種族と職業**: 種族ごとに就ける職業が決まっています（`races.json` の `allowedClassIds`）。
  神官はヒューマンとエルフだけ、といった制約があるので、先に確かめます
- **体格(SIZ)**: 小柄なら6前後、大柄なら16以上。**レベルでは伸びない**ので、
  ここで決めた値が一生その人の体つきになります。素の装甲AVと積載上限を決めます
- **容姿(APP)**: 12以上でギルドポイントと戦闘中の士気回復にボーナスが付き、
  8〜12から離れるほど戦場で狙われやすくなります（`AppearanceSystem`）

### 2. 帯とレアリティを決める

| | F | E | D | C | B | A | S |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `defaultRank` / `recruitGuildRank` | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| `defaultLevel` | 1〜5 | 6〜10 | 11〜16 | 17〜24 | 25〜32 | 33〜40 | 41〜50 |
| 帯の既定 `recruitWeight` | 100 | 60 | 40 | 20 | 10 | 10 | 10 |

- `defaultRank` と `recruitGuildRank` は**必ず同じ値**にします。そのギルドランクに
  達するまで採用候補に出さないためです
- 帯より1段上のレアリティを置くときは `recruitWeight` を**必ず下げます**。
  `MasterLoader.DefaultAdventurerRarity` の帯（Rare=26〜45、Uncommon=46〜75）に
  収まり、かつ同じ帯の既定より低い値にします。マルシルもミカヤも30です。
  **帯の顔ぶれの中で目に見えて出にくいこと**がレアリティの中身なので、
  重みを下げずにレアリティだけ上げると、ただ強いだけの人になります

### 3. 能力値をスクリプトで組み立てる

`scripts/adventurer_stats.py` が素質とレベル成長を分解して計算します。手で足し算
しないでください。成長点の配分は「種族の成長率＋職業の成長率＋下駄0.2」の比で
5能力へ配るもので、暗算に向きません。

```bash
python3 .claude/skills/add-adventurer/scripts/adventurer_stats.py plan \
    --race Race_Human --class class_Healer --level 8 --rarity Rare \
    --con 6 --app 13 --base 9,15,6,10,11 \
    --id adv_0030 --name ミカヤ --gender Female
```

`--base` は **Lv1時点の** 体力,精神,筋力,敏捷,知力です。合計が
「素質 − 体格 − 容姿」に一致しないとエラーになります。省略すると成長率どおりの
機械的な配分を出しますが、それは**全員が同じ顔になる配分**です。目安として受け取り、
「神官だから精神を厚く、小柄だから筋力は薄く」のようにその人らしい形へ寄せてから、
`--base` で渡し直してください。

出力される雛形の `defaultWeaponId` と `background` は空なので埋めます。
初期装備は職業の看板に合わせます（`references/roster.md` に一覧）。防具は全員
`eq_cloth_01` です。`id` は既存の最大 + 1（`adv_0031` のような連番）。

### 4. ユニークスキルを持たせるなら

`skillIds` に書いたスキルは、雇った瞬間から効き、習熟度を要求せず、職業を変えても
外れません。**その人にしかできないこと**を1つだけ渡す枠です。

- `classes.json` の `classSkills` には載せません（載せると誰でも取れて固有でなくなる）
- `family` は空にします。段階スキルの束に混ぜると、同じfamilyは最上位1つしか効かない
  仕様のせいでマスタリー側と押しのけ合いになります
- 職業の看板と噛み合う装備条件を付けます。神官のミカヤの「銀色の髪の乙女」は
  `requiredWeaponType: 9`（光魔法）を条件にしています
- 効果は `skills.json` の既存項目で足りるか先に確かめます。足りないときだけ
  `SkillBattleEffect` などへ項目を足し、`MasterLoader.ParseBattle`・
  `EquipmentText`・`TraitMasterData` の3か所と MASTER_DATA.md の表を同時に更新します
  （どれか1つ忘れると、読み込まれない／画面に出ない／特性の検査をすり抜けます）

### 5. 検算する

```bash
# 規則との突き合わせ（素質・レベル帯・重み・種族と職業・Lv1で1未満にならないか）
python3 .claude/skills/add-adventurer/scripts/adventurer_stats.py check adv_0031

# 名簿全体を見て、帯の中での立ち位置を目で確かめる
python3 .claude/skills/add-adventurer/scripts/adventurer_stats.py audit

# ID参照とマスタ全体の整合
dotnet run --project GuildSimulator.Cli -- --validate-master
```

`--validate-master` の「ランク帯の逸脱」は**エラーではありません**。追加前と同じ件数の
ままなら、今回の変更が原因ではないので放置してかまいません（追加前に一度実行して
件数を控えておくと判断が早いです）。

### 6. ドキュメントとテスト

- **MASTER_DATA.md の「冒険者名簿のランク配分」**: 冒頭の人数（「冒険者30人は
  F 18人 / E 7人 / D 5人」）を必ず直します。ここが古いと、次に足す人が
  誤った前提で数えます
- **テスト**: `GuildSimulator.Tests/` に、その冒険者の位置づけを固定するテストを足します。
  能力値を1つずつ並べるのではなく、**規則のほうを固定します**（素質がいくつか、
  帯の中でどれだけ上か、上限を超えていないか）。数値の羅列は、あとで帯ごと
  調整したときに意味もなく赤くなるだけです。`MikayaHealerTests` が手本です
- ユニークスキルを足したなら、その効果が実際に効くことも戦闘を回して確かめます

```bash
.\tools\test-fast.cmd                       # Windows
dotnet test GuildSimulator.Tests/GuildSimulator.Tests.csproj -c Debug -m:1 -nr:false
```

## 参考

種族・職業の一覧と成長率、初期装備、名簿の実測値は `references/roster.md` に
まとめてあります。職業や種族を選ぶとき、既存の顔ぶれと被っていないか見たいときに開きます。

CIはPRでは走りません（`main` へのpushのみ）。マージ前に上のテストと
`--validate-master` をローカルで通しておいてください。
